# Windows 浏览器启动版设计

日期：2026-08-28

状态：待用户审阅。用户已选择“启动后自动打开浏览器”的路线；本文提出首版完整边界，不代表代码已实现、安装包已生成或通过验收。

## 1. 目标与范围

首版目标为 Windows x64：用户无需自行安装 Python、Node.js 或开发工具，安装或解压后双击八股助手，即可在默认浏览器中使用现有界面。

复用 `bagu.py` 的业务逻辑和 `web/index.html` 唯一页面。新增桌面发行入口，不改抽题、会话锁、调度、评分及 submission 重放协议，不改变 Android 私有目录和安全边界。

本次采用浏览器启动器，不引入 pywebview、Electron、Tauri 或新的前端框架。共享 Python 核心和启动器仅使用标准库；PyInstaller 只用于隔离的构建环境，作为本方案需要确认的构建工具例外，不加入应用的业务依赖。

首版交付 public 空题库包。暂不实现内部种子包、自动更新、托盘图标、开机自启、Windows 服务、独立答题窗口、macOS 或 Linux 包。

## 2. 路线选择与交付

已比较浏览器启动器和独立窗口：浏览器路线能够复用当前浏览器语音与存储行为，减少宿主维护；代价是关闭标签页与退出后台需要分开处理。用户已选择浏览器路线。

采用 PyInstaller `onedir` 构建，并从同一份经过验证的目录产物生成：

- ZIP 解压运行包：必须完整解压目录，不只复制 EXE。
- Inno Setup 安装包：面向普通用户，提供开始菜单入口和可选桌面快捷方式。

ZIP 是免安装程序包，不承诺数据随目录移动。两种包均使用同一个当前用户数据目录；替换程序目录不覆盖数据。安装包采用当前用户安装，不要求应用以管理员身份运行。

先验证目录包，再生成并验证安装包。缺少安装器工具或干净系统验证时，只能报告已完成的产物和未验证项，不能将目录包验证冒充安装包验收。

## 3. 启动与退出

新增独立桌面入口，保持现有 `python bagu.py serve` 默认行为和 Hermes CLI 协议不变。

启动顺序：

1. 确定资源目录和当前用户数据目录，检查必需资源、写权限与版本信息。
2. 获取该用户数据目录的实例锁；同一数据目录只允许一个桌面服务实例。
3. 准备数据库；首次创建空库，已有库按第 4 节的升级规则处理。
4. 绑定仅本机访问的端口，启动服务并通过带鉴权的就绪检查。
5. 打开默认浏览器。启动失败显示可读的 Windows 错误提示，不留下不可见的失效后台。

发行版固定使用 `http://127.0.0.1:18765`，与源码版默认的 `8765` 分开。端口不可用时明确报错，不静默改用随机端口，不关闭或接管其他程序，也不修改源码版端口。

重复启动必须根据实例锁及带随机实例身份的鉴权握手确认已有服务，再重新打开页面；不能仅凭 PID、端口占用或任意 HTTP 200 判断。处理首次启动并发和陈旧运行记录，等待时间有上限。

关闭浏览器标签页不终止服务；用户可以再次双击图标继续使用。发行版页面提供“退出八股助手”入口，安装版还提供开始菜单退出入口。退出执行同一套受保护的本地控制逻辑，不使用 PID 强杀。

退出前阻止新的写操作，检查正在进行的模型评卷、导入、备份及其他文件或数据库操作。忙碌时拒绝退出并说明原因；检查与停止接收新操作之间不能留竞态窗口。未完成但空闲的练习可以保留，退出不得隐式 `skip` 或修改调度；下次启动继续原会话。

正常退出关闭监听、释放实例锁并清除本实例运行记录。崩溃恢复不得依靠旧 PID 杀进程。不能可靠打开浏览器时，给出可重试入口或明确错误，不要求用户寻找隐藏终端。

## 4. 数据与配置

使用现有 `AppPaths` 注入路径，发行版数据根目录为 `%LOCALAPPDATA%\BaguHelper\`：

| 子目录 | 内容 |
| --- | --- |
| `data/` | 用户 SQLite 数据库 |
| `config/` | `settings.json` 和仅包含模型密钥的 `.env` |
| `logs/` | 脱敏日志，保留现有日志大小与轮转约束 |
| `runtime/` | 实例锁及短期运行记录 |
| `backups/` | 数据库升级前的完整 SQLite 备份 |

静态资源从安装目录或解压目录读取，不从当前工作目录寻找；数据库和配置不能写进 PyInstaller 资源目录或临时解压目录。

不得自动读取或复制仓库里的 `bagu.db`、`.env`、`settings.json`、历史备份或 Android 数据。现有用户通过界面主动导入 `.bagu-backup` / CSV 迁移内容，模型配置另行填写。

源码 CLI 继续使用原路径，不悄悄切换到发行版数据。会话约束仍按每份数据库成立；发行版请求全部显式使用自己的数据库连接和配置目录。

已有数据库若需要迁移，先使用 SQLite 备份接口生成完整备份并验证可读取；备份失败则中止升级。不得用 `.bagu-backup` 替代完整数据库备份。高于程序支持版本的库拒绝打开，不降级或重建；失败保留原库并提供恢复说明。

数据库、配置和密钥不因程序更新或普通卸载而自动删除。清理数据不纳入默认卸载行为。

## 5. 浏览器状态与本地安全

### 稳定浏览器状态

发行版使用固定 origin，继续沿用桌面 `localStorage` 保存草稿、当前 submission 和练习模式，不创建第二套答案存储。

重启服务后，同一浏览器配置文件可以恢复草稿；换浏览器、隐私窗口或清理浏览数据不保证保留草稿。源码版与发行版端口不同，草稿不自动互通，正式使用文档需要明确说明。

### 访问控制

发行版独立启用每进程随机访问令牌，所有业务 API、诊断及退出控制均验证令牌、预期 Host，并拒绝异源浏览器请求；不启用宽泛 CORS。只监听 `127.0.0.1`，不开放局域网访问。

浏览器启动凭据放在 URL fragment，不能放在 query、日志、错误信息、诊断包或外部链接中。前端读取后立即清除 fragment，并将本次凭据保存在页面内存及当前标签页的 `sessionStorage`，用于刷新页面；模型 Key 仍只在后端 `.env`。

首页可返回不含秘密的启动页面；业务和控制数据只能在鉴权后访问。桌面模式由发行版服务明确标识，不能只凭用户提供的查询参数启用；普通源码网页和 Android 保持各自行为。

重启服务使旧令牌失效。旧标签页应显示重新打开应用的提示，保留草稿，不自动提交答案或重复计分。

运行记录如包含控制凭据，必须以当前用户专属权限创建；权限设置失败时启动失败，不能继续留下可被其他普通用户读取的令牌。读取运行记录仅接受预期的 loopback 地址、固定端口和严格字段，不跟随重定向，不向外部地址发送令牌。该边界不声称防御已控制同一 Windows 账户的恶意程序。

设置 `Referrer-Policy: no-referrer`、禁止嵌入和资源类型嗅探，并保持资源显式允许列表；不开放任意本地路径。新增保护不能误伤模型流式响应、备份下载、允许的答案图片或诊断功能。当前诊断路由的特殊鉴权不能成为绕过桌面统一鉴权的入口。

## 6. 首次运行

public 包初始化为空题库，复用已有空状态引导用户导入 CSV / `.bagu-backup` 或手动添加题目。

无模型配置时可以使用题库答案背题自评；AI 评卷由用户自行配置模型服务。不得携带维护者 API Key、默认收费凭据或把第三方题库当作应用源码许可的一部分打包。

不在启动时自动联网抓题、安装其他软件或检查更新。语音能力继续依赖用户浏览器及其服务，验收报告标明实际测试的浏览器和未支持情况。

## 7. 构建、版本与更新

建议职责划分：

- `desktop/`：Windows 启动、实例管理和发行版 HTTP 适配；不复制评分或题库业务。
- `scripts/`：桌面构建、打包清单和产物验证。
- `test/`：桌面运行时与打包测试，遵循现有 pytest / Node 约定。
- `web/index.html`：最小限度增加发行版启动鉴权、退出入口及相应状态；保持唯一页面。

使用项目本地隔离的构建环境，固定经验证的 PyInstaller 版本。版本显示和文件名读取现有 `version.json`，不擅自递增 Android versionCode 或制造另一份版本真相。

应用资源采用显式允许列表：唯一网页、已有品牌图片、本地字体及许可、版本元数据和必要运行时许可。不得递归拷贝仓库、`assets/` 全目录、测试、文档截图、开发工具或任何个人数据。依赖运行时的打包清单与第三方许可需要核对。

产物存于已忽略的 `dist/windows/<version>/public/`，使用独立构建工作目录，不覆盖 Android 产物。验证回执记录源码状态、构建工具版本、精确产物大小和 SHA-256；工作区脏时必须记录这一事实，不能声称对应某个纯净 commit。

首版手动更新：用户退出旧版后安装新版或替换完整解压目录，保留用户数据。安装器不得直接替换运行中的文件，不强杀应用，不自动结束练习。保留数据不意味着数据库可用旧版本回滚。

不自动提交、推送、上传 Release、购买签名证书或使用现有签名凭据。Windows 未签名状态和可能出现的系统信誉提示需如实说明，不要求用户关闭系统安全防护。

## 8. 验证与完成标准

先写失败测试再实现最小功能；使用临时目录和假令牌，不读写真实题库或模型 Key，不调用真实模型。

测试矩阵包括：

- 启动、重复启动、两个启动器并发、端口被无关服务占用、陈旧记录、浏览器打开失败、资源缺失和目录不可写。
- 错误或缺失令牌、恶意 Host / Origin、跨源请求、诊断鉴权、路径穿越和令牌脱敏。
- 正常退出、忙碌拒绝、退出与新请求并发、空闲 open 会话保留及下一次恢复。
- 首次空库、已有库不被覆盖、迁移前完整备份、备份失败、更高 schema 拒绝和配置隔离。
- 浏览器刷新、服务重启后令牌失效、草稿保留、submission 恢复、流式评卷、下载与退出 UI。
- 包内资源与许可允许列表、个人数据排除、版本一致性、ZIP 完整目录和安装器产物一致性。

运行与修改相关的新测试，并回归核心、网页和 Android 项目契约。涉及公共 HTML 的变更须验证 Android 不受影响；Python 测试通过不能替代实际浏览器、EXE 或安装器验证。

在未安装 Python 的干净 Windows 环境，以普通用户验证精确交付物：解压启动、中文及空格路径、安装、重启恢复、端口冲突、升级保留数据、卸载保留数据。至少记录实际 Windows 版本和默认浏览器。不能将开发机运行成功标记为干净环境验收通过。
